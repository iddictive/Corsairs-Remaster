# Потери графики относительно исходного движка

Проверка исходников и отдельных Metal-компонентов от 14 октября 2026 года.
Это перечень подтверждённых проблем, а не полное сравнение игровых кадров.
Исходный Windows-код и импортированные настройки служат базой сравнения;
принимающий runtime — установленное приложение Metal.

После аудита пользователь запросил исправить весь подтверждённый объём.
Первая партия солнца/звёзд/отражений установлена; последующий игровой кадр
открыл повторный ремонт маленького солнца. Полная исправленная партия, включая
шторм и видео, установлена через канонический staging: signed engine987efaf3.
Ниже сохранены причины потерь и результаты исправлений. Компоненты не заменяют
окончательный игровой replay.

## Шторм сохраняет мелкие волны

В дефектной партии `weather-engine.patch` каждый кадр заменял амплитуды формулами
`.35 + wind*.16` и `.15 + wind*.035`. При ветре30 их сумма равна6.35.
Исходный `PROGRAM/weather/WhrSeaPresets.c`, профиль `storm`, задаёт64 и9.
Это коэффициенты heightfield; отношение11.5 не является измерением высоты гребня.
Обе реализации `SEA::WaveXZ` действительно используют эти амплитуды для высоты
воды и нормалей, поэтому усиление shader bump эту потерю не устраняет.

При естественном начале шторма нативная погода также не переключает геометрический
профиль: `Whr_NativeChanged` обновляет флаги дождя/шторма, а начальный выбор пресета
происходит после очистки `WeatherParams.Storm` в `WhrWeather.c`.
Масштабы, скорость анимации и острота волн могут остаться от спокойной воды:

| Параметр | Calm | Исходный storm |
| --- | ---: | ---: |
| Scale1 / Scale2 | 1.25 / 2 | .075 / .5 |
| AnimSpeed1 / AnimSpeed2 | 1 / 1.25 | 4.25 / 8 |
| PosShift | 2 | 4.25 |

Меньший `Scale` растягивает рисунок в мировом пространстве. Полный повтор
первого128² heightfield должен меняться с102.4 до1706.7units; это размер тайла,
а не длина каждого гребня. Даже когда исходный storm preset попадает в SEA,
его `FoamV=42` несовместим с нативной суммой амплитуд6.35: обычная волна
не достигает порога пены.

`WhrSea.c` и `WhrSeaPresets.c` в composed runtime совпадают с импортированными
входами. Изменённая нативная интеграция владеет потерей. Исправление должно
восстановить согласованные амплитуду, масштаб, анимацию, остроту и пену через
единственный авторский профиль и непрерывную силу шторма. Отдельные числовые
копии пресетов в C++ создадут второго владельца этих настроек.

Проверка будущего ремонта: уже созданное спокойное море → шторм → восстановление;
сравнение высот/пространственного масштаба и пены с исходным storm profile.
Сохраняются ограничения воды у берега, в локациях и каюте. Их текущий cap может
оставаться от входа в сцену; поднимать его без проверки владельца нельзя.
Цунами и водоворот добавляют собственную геометрию после обычного sampler.
Первый аудит был только чтением; последующий ремонт выполнен в прямых
`engine/src/libs/sea` и канонических `WhrSea.c`/`WhrSeaPresets.c`. Банк обычных
и штормового профилей получает значения из того же авторского switch.
`UpdateWeatherWaveProfile` непрерывно смешивает геометрию/пену по настоящему
`WEATHER_BASE::GetStormStrength`; отдельных копий пресетов в C++ нет.
Повышение cap сохраняет текущую амплитуду и плавный рост, снижение ограничивает
её сразу. Часовой refresh обновляет дневную/ночную пену; места/каюты исключены.

Нативный sampler на64 реальных кадрах высот проходит штиль→шторм→восстановление:
размах выборки1.4373→31.8906, амплитуды63.9987+8.9997, повтор1706.6units;
пена появляется в2347 из30000 штормовых точек. Проверены cap6/0, берег, остров,
каюта, независимые исходные профили и сохранение добавленной геометрии событий.
Старый runtime без банка сохраняет авторский Sea2.

Проверка полного `AttributeChanged` с настоящими `ATTRIBUTES` выявила:283 записи
вложенного банка вызывали281 изменение живого моря. Уведомления потомков
`NativeSeaProfiles` теперь остаются данными; только `NativeSeaProfilesReady`
публикует банк. Первая загрузка и часовой refresh дают0 живых изменений;
прямые записи Sea2/Fog продолжают работать. Исправлена и подводная камера:
прежний `z && bStarted` подменял мировую координату нулём/единицей. Авторская
плоскость SimpleSea и явный допуск цунами/водоворота сохранены.

## Солнце выглядит белой точкой

Первый процедурный диск появился, но физический размер и слабый ореол не дали
читаемого источника. Новый shader добавляет компактное оптическое свечение и
мягкий угловой спад. Радиусы вклада≥64/32RGB —37/50px при1280×720/FOV1.2,
как у исходной `sun1` при авторских300/3500; реальный Device даёт36px для≥64RGB.
Проверены атмосферный спектр, opaque/thin/split облака, отсутствие квадратных
краёв и очистка состояния. Текстура солнца служит только независимым ориентиром.

## Отражения кораблей смещаются на наклонной воде

Плоская вода проходит сравнение с независимо отражённой геометрией. При наклоне
нормали единственная точка кубического захвата не совпадает с фактической точкой
отражения на воде. Отдельная ошибка проекции подтверждена в modern SimpleSea.
Механизм, отвергнутая экранная трассировка и текущий ремонт принадлежат
[`sea-reflections.md`](sea-reflections.md); игровая приёмка остаётся открытой.

## Видео пропускаются

В исходной партии `xinterface/src/aviplayer/aviplayer.cpp` декодирование и показ были закрыты
`_WIN32`; нативный `PlayMedia` возвращаетfalse. Скриптовый `StartVideo` по-прежнему
использует этот потребитель, поэтому заставки и сюжетные ролики не показываются.
Для восстановления нужен нативный декодер/вывод с прежним скриптовым завершением.
Это отдельная потеря видеопути, не дефект шейдера воды.

Ремонт использует AVPlayer/AVPlayerItemVideoOutput: аудио и часы принадлежат
проигрывателю, BGRA-кадры идут в существующую текстуру интерфейса. SDK отвергает
оригинальные WMV3/WMAv2 с AVFoundation−11828. `src/assets/video/manifest.json`
связывает15 оригиналов с H.264/AAC-рецептом: staging готовит `.wmv.mp4`-соседей,
сохраняя оригиналы. Точные пути входят в обычные delivery receipts/экспорт.
Проверенные данные повторно используются без FFmpeg; при первой подготовке
он нужен только как инструмент, сторонний codec runtime не поставляется.

Проверены94 меняющихся кадра Seaward до конца,261 кадр France/02 с исходным
анаморфным aspect1.363636, уничтожение/skip, неподдержанный/отсутствующий файл,
подготовка15 видео и повтор без энкодера. Удалён Wine-обход, который настройкой
«пропускать стартовые видео» отключал также сюжетные ролики; startup skip
остаётся в `Main_LogoVideo`. Полный `seadogs.c` с будущими скриптами/shared headers
компилируется без выполнения Main. Игровой показ/звук остаются отдельным replay.

## Подозрения, которые исходники не подтвердили

- Пена, береговой эффект, каустика, частицы и прозрачность имеют действующие
  Metal-потребители. Их наличие не доказывает правильность каждого игрового кадра.
- Все14 найденных авторских texture-combiner операций входят в поддержанный набор.
- `SetClipPlane` уже был пустым в исходном движке; backend stub сам по себе
  не доказывает новую потерю. Gamma проходит через `SDLWindow::SetGamma`.
- Загрузчик raw/DDS и mip-уровней реализован в используемой базовой зависимости.
- Закомментированный `particles_inv` совпадает с исходным движком.

Для сравнения внешнего вида ещё нужны одинаковые игровые условия: береговая пена
и след корабля, плотный дым/огонь, растительность на сумеречном фоне. Автономный
запуск игры, управление и чтение player SAVE для этого аудита не выполнялись.
