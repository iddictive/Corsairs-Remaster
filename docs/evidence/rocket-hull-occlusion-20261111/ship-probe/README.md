# Rejected hull-effect prototype

The isolated Metal probe renders an opaque 32 × 7 × 8 box representing a hull, a depth-writing water plane, and an actual `ClusterImpactRenderer` impact at (0, 8, 6), with input radius 12.6 and warhead 1. It samples 0.12, 0.55 and 1.40 seconds from observers at z=+85 and z=-85. `moving-*` translates the box four metres in x while the impact remains at its initial world position; it is a displaced-state check, not a continuous moving-ship simulation. The scene uses a simple box, not an actual ship mesh or gameplay.

`before-*` is the existing land-style renderer; `after-*` is a rejected candidate that extends its volume downwards and maps Other to a new hull surface. The candidate initially produces a flash but is largely hidden by the box at 0.55 seconds from both sides. It is not an accepted solution. The opaque box and water remain depth-occluding. The distinct `Other` input also represents debris, so mapping every Other impact to hull would be incorrect without identifying the hit entity. The candidate changes have been removed from production files.

For reproduction, copy either probe into an empty temporary directory as `probe.mm` alongside `cluster_impact_render.hpp`: use this directory's header for `candidate-probe.mm`, or the parent directory's frozen header for `baseline-probe.mm`. Compile from the project root with `xcrun clang++ -std=c++20 -O1 -fobjc-arc -framework Metal -framework AppKit <temporary>/probe.mm -o <temporary>/probe`. Run from the project root with `SIDE=1 MOTION=0 <temporary>/probe <empty-output-directory> single 1`; use `SIDE=-1` for the opposite observer and `MOTION=4` for the displaced box. The fixture loads the same VFX assets as the original standalone renderer fixture. Each output contains count-zero and count-one frames and GPU timing samples; the samples are too few for a performance verdict.

The live backend stores impact position in world coordinates with no struck ship identity, local anchor, hull bounds, or waterline. A hull-attached effect therefore needs its producer to identify the winning traced ship and feed an attachment contract whose current transform and lifetime are updated by the owning ship; it must distinguish debris and handle entity destruction. An effect that reaches the actual waterline also needs water height or a supported water intersection. The renderer can then consume this data while preserving scene-depth clipping. `ship_phonk_laser.cpp` already demonstrates ship-local hits transformed with the current model matrix.
