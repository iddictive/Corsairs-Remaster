# Nuclear foam material separation

The existing nuclear wave triggered `Sea2_Foam` but its material values were merged with tsunami/vortex values, and the shader only selected event foam for tsunami or whirlpool. With neither active it fell back to height-driven authored foam. The nuclear crest therefore gained ordinary foam from its own displacement, even when ordinary weather foam was enabled independently.

The candidate passes the ordinary-event and nuclear masks separately in a 52-byte sea vertex. It also passes signed nuclear height so the ordinary foam coverage can use the underlying non-nuclear surface. The shader keeps the existing tsunami/vortex computation, then adds a nuclear-only contribution from the separate breaking mask. This retains the original branch when no nuclear wave is active; overlap is not encoded as a maximum of the two materials. Ordinary wave geometry and the tsunami evaluator were not edited.

`comparable-before/` and `final/` are isolated full-scene, 1280×800 hidden fleet runs of the same single tier-1 blast and fixed 16 ms simulation delta. They use identical hashed `lib/*.a` and backend source; the baseline uses `baseline-source/` while the candidate uses `current-source.patch`. Baseline ran after candidate. The candidate run's overall source fingerprint changed during the run, so whole-project source stability is not established. The CPU wall time around `core_internal.Run()` for frames 120–239 was p50/p95 **8.497/9.405 ms before** and **8.577/9.389 ms after**. These 120 samples do not measure GPU completion, player FPS, long-lived waves, saturation or variance over sustained load. The before and after frames are `comparable-before/scene.png` and `final/scene.png`.

`overlap-valid/` is a short synthetic tsunami-plus-nuclear run. It recorded one active nuclear wave and `[OverlapProbe] serial=1 height=41.8539 foam=0.1902` for the tsunami at the selected point. Its scene confirms the fixture ran with both effects, but the large tsunami occupies the view and does not provide a clear perceptual isolation of the two contributions. A first overlap attempt used a source too far from the camera and is not an acceptance result. Source-level channel separation does not prove every simultaneous visual state.

`before.py`, `replay.py` and `overlap.py` are the bounded fixture variants; invoke through `codex-run-scratch`, `nice -n 15`, `FLEET_COMBINED=1`, `WAVE_ABLATE=0`, `WAVE_PICTURE=1` and an existing `WAVE_EVIDENCE_DIR`. They depend on the fixture under `../slow-wave-20261111/fixture`, installed RESOURCE assets, and the recorded build libraries. The initial attempted 640×400 run exited 70 because the fixture's actual backbuffer stayed 1280×800; the retained valid runs use the correct size.

The scene is not the installed game, and one frame cannot prove motion, eliminate distant tiling, establish perceptual acceptance, or verify GPU cost. The wave remains a rounded ring in the single-blast image; the final look needs inspection in the user's runtime. No game, save, shared build or installation was operated by this replay.
