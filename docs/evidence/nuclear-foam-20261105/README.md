# Nuclear foam investigation

The reported frame showed a ship beside an island under dark smoke, broad concentric crests, and dense diagonal white stripes across the foreground water. Source inspection found that `nuclearWavesActive` forces the additive `Sea2_Foam` pass, but the Metal event-material branch checks only the tsunami envelope and whirlpool. Nuclear-only waves therefore use authored foam, whose alpha derives from surface height. This mismatch is established in source; its contribution to the screenshot has not been isolated in the game renderer.

The included images are exploratory Metal **planar approximations**, not game captures. They show three overlapping synthetic radial envelopes on a flat water colour over a 1,200-by-1,200-unit area, with no perspective, island, mesh, lighting, fog, vertex interpolation or actual render blend state. `before.metal` approximates height-driven authored coverage using the PENA texture; `seafoam-55.metal` uses the existing `seafoam_2.tga.tx` red channel with synthetic per-event foam at 55 units per tile. The latter eliminates the dense linear pattern in this approximation, but repetition is still visible and no actual rendering or quality acceptance is established. The real material combines tsunami, whirlpool and nuclear values by maximum, so overlapping event types cannot be independently shaded from the current vertex fields.

The existing `seafoam_2.tga.tx` is already used by `SEAFOAM` as `carcassTexture`. It has 512×512 pixels, five mip levels and format 21 (`A8R8G8B8`); PENA has seven levels and format 22 (`X8R8G8B8`). Any proposed separate resource must be loaded/released by `SEA`, bound separately, and preserve ordinary foam and other event types, including overlap. No shader candidate was applied.

## Reproduction and limits

The two exact shader inputs and rendered images are retained here. The fixture is `docs/evidence/tsunami-foam-20261104/probe.mm`, built with Apple clang 21.0.0 and macOS SDK 27.2 on Apple M5 Max. Its hardcoded log says 180×180, but these shader inputs use 1,200×1,200; that log label is not applicable. It requires a 512×512, seven-level, format-22 TX, so the seafoam experiment used a temporary copy with its header changed to 22 and two nearest-neighbour mip levels appended; the probe reads all data as BGRA8 and the shader uses only red. This does not validate the native texture loader, its alpha, or mip handling. Input PENA SHA-256 was `ac356b4e560652ca46d6b7a378780b1f833d885ec37b3cef1105448e8e0be878`. Reconstruct the temporary seafoam fixture by copying the five existing levels and appending 16×16 and 8×8 nearest-neighbour levels from the preceding level, changing header integers 3 and 4 to 7 and 22 respectively. Compile and invoke the probe as documented in the earlier foam investigation, supplying either retained Metal input and the corresponding TX; time argument 0 generated the retained images.

The exploratory timings were highly unstable under concurrent GPU load: the seafoam 55-unit case ranged from 0.0216 to 1.155 ms for the same 1024² offscreen draw. They do not establish FPS or comparative cost. `tools/run_sea_benchmark.py` measures an engine-linked hidden fleet, but its current fixture contains neither nuclear waves nor island geometry and deliberately refuses to compete with a running game. A moving, perspective, multiple-wave workload and paired full-frame timings remain necessary before acceptance.
