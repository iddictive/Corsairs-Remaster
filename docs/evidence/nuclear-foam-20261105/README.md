# Nuclear foam investigation

The reported frame showed a ship beside an island under dark smoke, broad concentric crests, and dense diagonal white stripes across the foreground water. Source inspection found that `nuclearWavesActive` forces the additive `Sea2_Foam` pass, but the Metal event-material branch checks only the tsunami envelope and whirlpool. Nuclear-only waves therefore use authored foam, whose alpha derives from surface height. This mismatch is established in source; its contribution to the screenshot has not been isolated in the game renderer.

The subsequent [footprint and anti-tiling comparison](footprint-antitile-20261105/README.md) evaluates the installed first correction against a wider nuclear mask and the existing texture sampler in an engine-linked synthetic scene; in-game acceptance remains open.

The included images are exploratory Metal **planar approximations**, not game captures. They show three overlapping synthetic radial envelopes on a flat water colour over a 1,200-by-1,200-unit area, with no perspective, island, mesh, lighting, fog, vertex interpolation or actual render blend state. `before.metal` approximates height-driven authored coverage using the PENA texture; `seafoam-55.metal` uses the existing `seafoam_2.tga.tx` red channel with synthetic per-event foam at 55 units per tile. The latter eliminates the dense linear pattern in this approximation, but repetition is still visible and no actual rendering or quality acceptance is established. The real material combines tsunami, whirlpool and nuclear values by maximum, so overlapping event types cannot be independently shaded from the current vertex fields.

The existing `seafoam_2.tga.tx` is already used by `SEAFOAM` as `carcassTexture`. It has 512×512 pixels, five mip levels and format 21 (`A8R8G8B8`); PENA has seven levels and format 22 (`X8R8G8B8`). Any proposed separate resource must be loaded/released by `SEA`, bound separately, and preserve ordinary foam and other event types, including overlap. No shader candidate was applied.

## Reproduction and limits

The two exact shader inputs and rendered images are retained here. The fixture is `docs/evidence/tsunami-foam-20261104/probe.mm`, built with Apple clang 21.0.0 and macOS SDK 27.2 on Apple M5 Max. Its hardcoded log says 180×180, but these shader inputs use 1,200×1,200; that log label is not applicable. It requires a 512×512, seven-level, format-22 TX, so the seafoam experiment used a temporary copy with its header changed to 22 and two nearest-neighbour mip levels appended; the probe reads all data as BGRA8 and the shader uses only red. This does not validate the native texture loader, its alpha, or mip handling. Input PENA SHA-256 was `ac356b4e560652ca46d6b7a378780b1f833d885ec37b3cef1105448e8e0be878`. Reconstruct the temporary seafoam fixture by copying the five existing levels and appending 16×16 and 8×8 nearest-neighbour levels from the preceding level, changing header integers 3 and 4 to 7 and 22 respectively. Compile and invoke the probe as documented in the earlier foam investigation, supplying either retained Metal input and the corresponding TX; time argument 0 generated the retained images.

The exploratory timings were highly unstable under concurrent GPU load: the seafoam 55-unit case ranged from 0.0216 to 1.155 ms for the same 1024² offscreen draw. They do not establish FPS or comparative cost. `tools/run_sea_benchmark.py` measures an engine-linked hidden fleet, but its current fixture contains neither nuclear waves nor island geometry and deliberately refuses to compete with a running game. A moving, perspective, multiple-wave workload and paired full-frame timings remain necessary before acceptance.

## CPU wave investigation

The retained [raw output](wave-probe-output.txt) and `wave-*.cpp` inputs are standalone CPU probes, not full-frame or game measurements. The [wave snapshot](wave-snapshot/shared/sea_nuclear_wave.hpp) preserves the experimental profile used by the probes; it is evidence, not the runtime owner. The host was Apple M5 Max, macOS 27.2, Apple clang 21.0.0, `-O3`, C++20. The unchanged geomorph and parallel helpers were taken from repository revision `8db8ed848b754d8b02840e5cf13d5926c3542e2b`.

Compile from the repository root with `xcrun clang++ -std=c++20 -O3 -Idocs/evidence/nuclear-foam-20261105/wave-snapshot -Iexperiments/native-metal/engine/src/libs/sea/src -Iexperiments/native-metal/engine/src/libs/util/include docs/evidence/nuclear-foam-20261105/wave-block-path.cpp -o /tmp/wave-block-path`; replace the source name for the other probes. The earlier distributed, coincident and sustained probes copy the old exact block test rather than the final margin-aware helper, exclude geomorph and compression costs, and the sustained probe prints a hardcoded `/480` despite creating 3600 records. The later block-path probe uses the actual margin-aware helper, double geomorph, candidate copying, compression, and tests height, both slopes, foam and load. Its 60/s synthetic scene retains 3160 active sources; neither it nor the ship-sampling loop measures the complete engine frame.

The ring-index prototype shows that exact spatial bins alone remain expensive for long-lived overlapping fronts. Its 200 and 350 damping trials were made by replacing `travel / 1000.f` in a temporary copy of the snapshot with `travel / 200.f` or `travel / 350.f`; neither is an accepted change. The field prototype uses the existing four-worker dispatch helper and linear interpolation; its measurements omit engine integration and use 3000 comparison points. The 64 m and 3200 m variants were produced by changing `step=32` to `step=64`, and `bins=48` to `bins=25`, respectively. The field and ring-index variants are exploratory, not installed. Their measured errors and unresolved cost exclude claiming visual quality, all-consumer coverage, or acceptable FPS.

The 48 m field prototype and moving/edge probes are also retained as separate sources. The four-worker field prototype covers 6144 m square and measures its candidate allocation, but excludes lookup, edge fallback, renderer and full frame. Production indices use `size_t` instead of its `int`, approximately doubling the retained candidate capacity in this fixture. The moving probes sample 36 hull points over 120 synthetic frames for one and four waves; threshold mismatches can occur around zero crossings, and they do not demonstrate gameplay visibility. The edge probe compares two samples 0.02 m apart at each inner and outer transition; it is a standalone reproduction, not a running-engine concurrency test. The current field has an exact fallback outside its camera window, so its worst-case cost is not bounded by the field probe.

`wave-publication-probe.cpp` exercises the standard-library atomic shared-pointer publication mechanism with four concurrent readers and repeated resets. It is not the engine, a thread sanitizer run, or proof that every engine writer is serialized.

The first engine-linked `field48-*` comparison exposed a large CPU regression. The next `field96-*` comparison removed that regression for tier 1, but exposed a strong positive surface bias and an underwater camera at tier 10. These are rejected intermediate candidates, not acceptance results. `wave-volume-probe.cpp` records the zero-integral crest/trough and bounded-response investigation. The latest model changes the width by scale; its source must be bound to the eventual combined engine fixture before any runtime or visual acceptance.

`fleet-wave-paired.py` rebuilds the two sea translation units and diagnostic driver into task-owned scratch, links both variants against identical existing engine libraries, and records CPU/GPU traces. In combined mode it separately rebuilds the current backend against the shader and supplies the same active uniform to the baseline fixture. The fixture uses 8 stock ships, one deliberately positioned at 12 km in matrix mode, a deterministic source at approximately 62.5/s or 1/s, and a fixed 16 ms simulation delta. It does not launch the player executable, load a save, or emit blast visuals. Its library hashes distinguish a paired frozen-link experiment from a full current-source build; native-source fingerprint drift and different scene states limit causal interpretation. Captured scene frames are synthetic fixture output, not gameplay acceptance.
