# Fleet-scene missile visual investigation

The portfolio request needs a readable missile with continuous exhaust against real ships and sea. These frames are diagnostic, not accepted portfolio assets or gameplay captures. The hidden, engine-linked fleet fixture loads no save and uses no player input; `fixture.cpp.txt` injects a single manually flying Oreshnik into the real renderer. The first fixture mistakenly replaced the missile each frame; `baseline.png` instead retains one missile throughout the flight. A hard-looking exhaust boundary remains.

The same 1280 × 800, 48-frame scene with only the smoke-particle fragment output disabled produced `no-smoke.png`; the conspicuous streak remains. This localizes that streak to the motor effect rather than the smoke sprites, but does not establish the cause of a reported installed-game defect. A candidate that faded the motor at its nozzle produced `rejected-fade.png`: it created a visible gap and was rejected. Neither candidate changed maintained game code.

A later scratch-only instrumentation of the continuous-flight scene counted 102 stored type-5 smoke puffs at the last emission. The emitter therefore ran in this fixture; this count does not prove that its smoke is readable in frame or diagnose the user's live gameplay.

The driver was compiled using the `sea-fleet-benchmark` Ninja command and the compile/link adaptation in `docs/evidence/particle-tracer-capacity-20261029/build-probe.py.txt`, adding the ship include and `STORM_METAL_SHIP_FIRE=1`. The isolated fixture used `docs/evidence/naval-ordnance-perf-20261104/nuclear-fixture.c`, the engine/ship/day/light fixture files from `docs/evidence/cannon-darts-20261021/native-fixture/`, and the runtime RESOURCE tree. It ran 48 frames at 16 ms with `STORM_METAL_MODERN_EFFECTS=1` and `STORM_QUIET_CLIENT=1`. Camera and missile setup are in the retained driver.
