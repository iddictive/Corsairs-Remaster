# Dawn and first-contact evidence

These records distinguish bounded source/Metal diagnostics from the player's
reported scene. `manifest.json` binds retained bytes to raw SHA256 values;
absolute repository/home and per-run temporary prefixes are normalized. The ordinary and Phonk
contact pairs preserve all192 CPU, renderer and physics/event rows. They measure
the first native wreck contour, with a labelled script-handler proxy; they do
not accept the first nonlethal production collision.

The canonical input owner is the native build-input release named in the root
README, SHA256 `da54154935a894e84ca3a9d95248a2586605c5f417ec5965a1b3490cb5439a89`.
Game assets remain installed inputs rather than copies in this evidence pack.
The source baseline is `999c349bc9a2c5d48b8939aee43adb800679c21a`; baseline contact
instrumentation adds only the same contour timing span used by the candidate.
Each run manifest records source and executable identities.

Frozen `.cpp.txt`, `.mm.txt` and `.py.txt` files are reconstruction inputs, not
permanent tests. Fog commands are retained in `fog/*/commands.json`; replace
`$REPO` with the current checkout and use a fresh task-owned temporary directory
for executable/output paths. The actual field integration and batch logs retain
separate correctness and dispatch-cost evidence. They do not measure a full
player scene.

For the contact diagnostic, restore `contact/run-contact.py.txt` into a task-owned
directory, replace its single `ROOT = Path('$REPO')` line with the resolved
checkout path, then run it once with `ordinary` or `phonk`. It uses the existing
`sea-fleet-benchmark` target, two ships,192 frames,1280×800 and the installed
resource owner. Build the target through the normal project build first;
the frozen script deliberately performs no build. The `STORM_METAL_CONTACT_DIAGNOSTIC`
mode is opt-in; ordinary benchmark behavior is unchanged. The frozen contour
and lifecycle probes retain independent geometry/cache oracles and raw results.
