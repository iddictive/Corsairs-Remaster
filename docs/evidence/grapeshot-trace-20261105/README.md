# Mast collision broad-phase experiment

2026-11-05. The sampled live battle (`experiments/native-metal/.cache/diagnostics/game-20261105-101337-27854.sample.txt`, disposable local diagnostic) showed 129 of 707 main-thread samples under `BallMastDistSq`; it did not record calls per frame or input distribution. No game UI was operated during this experiment.

The isolated baseline is `ship.cpp` from commit `2529d30`; the reversible candidate adds an expanded axis-aligned segment-versus-mast rejection immediately before the capsule calculations, preserving the original model and mast ray traces. No source change was applied. The benchmark loads the actual Brig1 model, calls `SHIP::BuildMasts` to populate six authored mast nodes and invokes the complete `SHIP::Cannon_Trace` with radius 0.4 and a script damage callback. It exercises far miss, near miss, capsule hit, direct ray hit, and starting inside a capsule, resetting mast damage each call. It is synthetic, not the measured battle's input stream. The separate three-shot sequence demonstrates accumulated mast 2 damage 0, 0.01, 0.02.

On Apple M5 Max, baseline and candidate respectively measured 0.082 and 0.049 µs per far miss, and 0.536 and 0.505 µs per mixed trace (20,000 calls each). Both produced the same aggregate trace result and damage, and the same three-shot outputs; this is not proof of per-input parity, floating-point boundary safety, RNG/save behavior, frame time, or a material battle improvement. The candidate is rejected pending realistic call counts and exact conservative bounds.

Reproduce in a new task-owned temporary directory on the same configured checkout/build: copy `setup.py.txt` and `bench.py.txt` into it as `setup.py` and `bench.py`, run `python3 setup.py` then `python3 bench.py`. The scripts compile isolated copies into that directory, link against the existing native build and use the local staged resource assets; they do not install or edit game source. The existing build's selected toolchain was `/usr/bin/c++` (Apple clang 21.0.0), macOS SDK at `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`, deployment target 15.0. This is a one-off diagnostic, not a game acceptance test.
